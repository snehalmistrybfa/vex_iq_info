OVERALL ASSESSMENT
================================================================================
The site is strong. The 30-day curriculum is complete, every day has a
Socratic hook, Think First, Concepts, Learn, Connect, Try It, a 1-2-3
rubric, and Reflect — matching the strategy spec exactly. All 76 video
cards exist and all internal #video- anchors resolve. The 6 concept pages
all have CSS diagrams and interactive Try It elements. The rubrics measure
evidence and reasoning, not just completion.

The 15 improvements below are ranked by priority. The top items are real
correctness/consistency gaps; the rest are polish and engagement.

#12 MEDIUM — Friction page "Good/Bad" sort allows wrong moves to count
      and never resets
================================================================================
Issue:
  The friction.html Try It (lines 60-90) is a sort-to-bin game. When a
  child sorts a chip into the wrong bin, the code (line 84) prefixes
  "Try again: " but still moves the chip into the bin and disables it
  (line 87). The chip is now stuck in the wrong bin with no way to retry
  or reset. The score (line 89) only counts correct sorts, so a wrong
  sort is permanent and the child cannot learn from the correction.

File and lines:
  friction.html lines 80-90 (the bin click handler)

Fix:
  On wrong sort, do NOT move the chip into the bin. Instead, keep the chip
  in the examples area, show "Try again!" feedback, and let the child pick
  the other bin. Add a "Reset" button that re-enables all chips and zeroes
  the score. This makes the activity a real learning loop instead of a
  one-shot with permanent errors.

#13 MEDIUM — Linkages page Try It slider only moves the tray vertically;
      the links rotate but do not show the parallelogram constraint clearly
================================================================================
Issue:
  The linkages.html Try It (lines 57-82) has a slider that rotates both
  links by the same angle and moves the tray up. This is a reasonable
  simplification, but the "level tray" claim (that the tray stays level)
  is not visually reinforced — the tray just translates up; it does not
  contrast with a swing arm that WOULD tilt. The concept's key insight
  (parallel bars keep the end level) is told in text but not shown
  comparatively.

File and lines:
  linkages.html lines 57-82

Fix:
  Add a small visual contrast: show a second "swing arm" tray (dashed
  outline, tilted) next to the 4-bar tray, so the child can see that the
  4-bar stays level while the swing arm tilts. Alternatively, add a
  toggle button "Show swing arm for comparison" that overlays a tilting
  tray. This makes the "why linkages" lesson visible, not just stated.
