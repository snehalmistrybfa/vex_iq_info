It is written so that future researchers can find the final 2-4 videos for each day and future developers can turn each day into a website lesson without inventing the pedagogy again.

PART 1: CURRICULUM OVERVIEW
===========================

Length and cadence
- 30 learning days, ideally 5 days per week for 6 weeks.
- 30-60 minutes per day. Build-heavy Days 11-12 may take 60-90 minutes or spill into another meeting; preserve the inquiry flow rather than rushing.
- Default session rhythm: Hook 2-3 min; Think First 3-5 min; Learn 10-18 min; Connect the Dots 3-5 min; Try It 15-25 min; Reflect/notebook 5-8 min.
- Every day creates a notebook artifact: prediction, sketch, data table, code screenshot, test result, decision, or reflection.

Six phases
- Week 1 / Phase A, Days 1-5: Become a game detective and mechanical thinker.
- Week 2 / Phase B, Days 6-10: Choose drivetrains and understand scoring mechanisms.
- Week 3 / Phase C, Days 11-15: Build, analyze, test, and improve Flop.
- Week 4 / Phase D, Days 16-20: Drive precisely and turn data into strategy.
- Week 5 / Phase E, Days 21-25: Build reliable driver-control code and sensor thinking.
- Week 6 / Phase F, Days 26-30: Create autonomous routines and become tournament-ready.

Pedagogical philosophy: curiosity before explanation, judgment after instruction
Every day begins with a phenomenon Arian can see, a constrained problem he can attempt, or a prediction he can make. The adult does not name the principle or demonstrate the solution first. Arian writes a hypothesis, tries something when safe, and becomes aware of what he needs to learn. Only then do the videos and short explanation supply useful language and mental models. This is the Socratic pillar: create the need to know first.

Every explanation is followed by performance. Arian must build, code, drive, measure, compare, or defend a decision. The rubric rewards evidence, controlled testing, explanation, and iteration—not copying the adult or getting a lucky result. The adult asks, "What did you observe?", "What evidence supports that?", and "What would you change next?" The adult may reveal safety rules and competition rules, but should not reveal the challenge answer. This is the evaluative pillar: guide judgment without spoon-feeding.

Coach/facilitator rules
1. Read only the Hook aloud first. Hide the Learn and Connect sections until Arian has written a prediction.
2. Give at least 3 quiet minutes and, when safe, one physical attempt before offering a hint.
3. Use a hint ladder: ask for an observation; ask what changed; ask for a comparison; point to a relevant video moment; only then explain a term.
4. Do not repair the robot, move blocks, or choose the strategy for him. Ask him to narrate while he changes one variable.
5. Protect productive failure. Stop only for safety, possible part damage, or an imminent rules violation.
6. Ask for a 1-2-3 self-score before giving adult feedback. Adult feedback should cite one piece of evidence and ask one next-step question.
7. End with a notebook entry labeled: Prediction / Test / Evidence / Next change.

Universal 1-2-3 rubric language
- 1 = Beginner: completed part of the task or made a guess, but evidence is missing or several variables changed at once.
- 2 = Developing: completed a fair test, recorded at least one useful observation, and can name a plausible improvement.
- 3 = Proficient: used repeatable evidence, explained why the result occurred with the day's concept, and made/tested one justified iteration.

Video ordering rule
Each day's final Learn list should contain 2-4 videos, ranked in viewing order by (1) conceptual clarity, (2) visual demonstration, (3) direct relevance to the day's challenge and Level Up, and (4) engagement for a fifth grader. A short non-VEX/LEGO physics visualization may rank above a VEX video when it teaches the mental model better; follow it with a VEX application video.

DAY 1 — THE LEVEL UP SCORE DETECTIVE
Phase: Week 1 / Game need and engineering questions
Target time: 45-60 minutes

Hook (Socratic puzzle): Two robots each move four Bean Bags. One earns far more points, while the other finishes sooner. How could both outcomes be sensible—and what would you need to know before designing either robot?

Think First: Before watching, sketch the field from memory and write three facts you think determine a winning score. Circle every fact you are unsure about.

Concepts: reading a game reveal critically; manual as source of truth; scoring breakdown; one-object possession; time, distance, accuracy, and goal-height tradeoffs; teamwork versus skills; turning game requirements into robot jobs.

Learn / video targets, ranked:
1. Reuse "Level Up Game Reveal" for energy, field overview, and visual context.
2. Reuse "Game Manual Breakdown" for how rules alter strategy; verify it matches the current manual before showing.
3. Reuse "Level Up Worlds Reveal" only as a second visual perspective or excitement clip.
Video search types/queries: "VEX IQ Level Up 2026 2027 official game reveal"; "VIQRC Level Up version 2.0 rules scoring"; "Level Up game strategy bean bags goals beginner".

Connect the Dots: A robot is not "good" in isolation; it is good at valuable game jobs under rules and time pressure. Higher goals promise more points but demand reach, stability, placement accuracy, and travel time, so the first design tool is a requirement-and-risk list, not a pile of parts.

Try It (evaluative challenge): Make a one-page "Team 295U Game Detective" sheet with columns for Job, Points/benefit, Difficulty, Robot feature needed, and Rule to verify. Add at least five jobs, then choose one as the first reliable scoring goal. Do not optimize yet.
Rubric: 1 = lists jobs without evidence; 2 = connects five jobs to scoring/manual facts and identifies uncertainties; 3 = compares value, time, and risk, cites rule sections, and defends a first-goal choice while naming what test could change the decision.

Reflect:
- What if a low goal can be scored twice as reliably as a high goal—what data would decide which is better?
- Which sentence in the manual changed one of your original guesses?

DAY 2 — WHY DOES ONE AXLE SPIN AND ANOTHER BIND?
Phase: Week 1 / Parts, connections, and friction
Target time: 45 minutes

Hook (Socratic puzzle): Build or hold two simple wheel-and-shaft assemblies: one supported cleanly and one crooked or rubbing. Why does the same motor seem stronger on one than the other?

Think First: Draw where you think energy is being lost. Before watching, label each unfamiliar part you believe could fix or cause the problem.

Concepts: beams, plates, pins, connector pins, corner connectors, standoffs, shafts, shaft collars, bushings/bearings, spacers, idler pins, shaft capture, two-point shaft support, alignment, friction, pin tool, proper versus forced connections.

Learn / video targets, ranked:
1. NEW: short VEX IQ visual on selecting/capturing/supporting shafts and reducing binding.
2. Reuse "VEX IQ 2nd Gen Kit Walkthrough" for part recognition.
3. Reuse "Getting Started with VEX IQ Gen 2" for safe setup and system context.
4. NEW: engaging VEX IQ pins/connectors/bushings build-basics demonstration.
Video search types/queries: "VEX IQ shafts bushings support friction"; "VEX IQ pins connectors standoffs beginner"; "VEX IQ building basics shaft collars spacers".

Connect the Dots: Motors do not deliver all their effort to the task. Misaligned holes, rubbing gears, squeezed wheels, and one-point shaft support spend effort as friction or flex; correct connectors and spacing create a straight, captured, freely rotating motion path.

Try It: Build two 10-minute axle test rigs that differ in exactly one support/spacing choice. Spin each by hand, then use the same motor speed and count coast time or rotations. Photograph both and annotate the force path and friction points.
Rubric: 1 = assembles a rig but changes many things or records no comparison; 2 = makes a one-variable comparison and records a clear observation; 3 = repeats the test, explains the role of support/alignment/capture, and improves the weaker rig based on evidence.

Reflect:
- What if you tighten/capture a shaft so well that it cannot slide at all—could that ever create more friction?
- Why do heavy arms need stronger shaft support than a light decoration?

DAY 3 — THE GEARBOX THAT LIES ABOUT “POWER”
Phase: Week 1 / Gears, speed, torque, and mechanical advantage
Target time: 45-60 minutes

Hook (Socratic puzzle): One gear train lifts a heavy load slowly; another spins fast but stalls. Both use the same motor, so where did the extra "strength" or speed come from?

Think First: Predict which will be faster and which will lift more: a 12-tooth gear driving a 36-tooth gear, or a 36-tooth driving a 12-tooth. Explain without using a formula.

Concepts: driver and driven gears; gear ratio; speed versus torque; mechanical advantage; direction reversal; idler gears; compound trains; efficiency; selecting ratios for drive, arm, and intake.

Video search types/queries: "VEX IQ gear ratio speed torque mechanical advantage"; "LEGO gear ratio visual for kids"; "VEX IQ M.A.D. Box gears".

Connect the Dots: Gears trade rotational speed for turning force; they do not create free energy. The tooth-count relationship predicts the trade, while friction, flex, and motor limits explain why the physical result is never perfectly ideal.

DAY 4 — MOVE A LOAD WITH ONE FINGER
Phase: Week 1 / Levers, linkages, chain, and elastic assistance
Target time: 45-60 minutes

Hook (Socratic puzzle): You must lift the same Bean Bag with one finger using a beam and pivot. Where would you place the pivot and push point so it feels easiest—and what do you lose in return?

Think First: Sketch three arrangements of load, effort, and fulcrum. Predict which gives the most force and which gives the most movement at the end.

Concepts: first-, second-, and third-class levers; effort/load/fulcrum; lever mechanical advantage; linkage motion; pivot friction; chain and sprockets for power transfer over distance; rubber bands as counterbalance/energy storage; tradeoffs between force, travel, and control.

Learn / video targets, ranked:
1. Seed candidate: "VEX IQ Building Basics: Levers" (video ID OQTAL8RsZaA), pending verification.
2. NEW: playful general-physics/LEGO lever classes visual for children.
3. NEW: VEX IQ chain and sprocket power-transfer demonstration.
4. NEW/optional: VEX IQ rubber-band arm counterbalance demonstration.
Video search types/queries: "VEX IQ levers mechanical advantage"; "three classes of levers LEGO for kids"; "VEX IQ chain sprocket arm"; "VEX IQ rubber band counterbalance arm".

Connect the Dots: The location of effort, load, and pivot decides whether a mechanism multiplies force, multiplies motion, or changes direction. Chain moves rotation to a distant shaft; rubber bands can help a motor fight gravity, but their changing tension also changes behavior through the motion.

Try It: Build a lever with movable fulcrum and effort points. Test two arrangements lifting the same bag, then add either a chain drive or rubber-band assist and compare effort, range, and controllability. Do not copy a finished lift.
Rubric: 1 = mechanism moves but positions are not identified; 2 = compares two arrangements and labels effort/load/fulcrum; 3 = explains the mechanical-advantage tradeoff, documents one controlled counterbalance or chain test, and selects an arrangement for a stated game job.

Reflect:
- What if the load moves twice as far from the fulcrum—what must happen to required effort?
- When could a rubber band make a lift less predictable even while helping the motor?

DAY 5 — THE TALL ROBOT THAT FALLS
Phase: Week 1 / Structure, center of mass, and stability
Target time: 45-60 minutes

Hook (Socratic puzzle): A tall robot and a short robot make the same sharp turn. Why might only one tip, and why might adding a heavy piece at the bottom change everything?

Think First: Draw a tipping line at the wheel edge and mark where you believe the robot's balance point is. Predict what happens when the arm reaches forward.

Concepts: center of mass versus support polygon; balance and tipping moment; momentum during turns/stops; wheelbase and track width; keeping mass low; square frames; bracing; triangulation; two-point connections; flex and structural integrity; useful and unwanted friction.

Learn / video targets, ranked:
1. NEW: clear hands-on center-of-mass/tipping demonstration for kids or LEGO robots.
2. NEW: VEX IQ structural bracing, square frames, and triangulation.
3. Reuse "How to Design and Build" for the engineering context.
4. NEW/optional: VEX IQ Tug of War center-of-mass/mechanical-advantage clip.
Video search types/queries: "VEX IQ center of mass tipping robot"; "LEGO robot center of gravity experiment"; "VEX IQ bracing triangulation strong frame".

Connect the Dots: A robot tips when the combined effect of gravity and acceleration moves beyond its support area. A wide, square, braced base and low central mass resist tipping and flex; a long raised arm and abrupt momentum make both worse.

Try It: Build a small tower on a rolling base. Find its repeatable tipping threshold on a gentle ramp or in a controlled turn, then change only one of mass height, base width, or bracing and retest three times. Use no human catching inside the measurement zone.
Rubric: 1 = changes the build without a baseline; 2 = runs a controlled before/after test and records results; 3 = repeats trials, explains the center-of-mass/support relationship, and makes a second evidence-based improvement without simply adding random parts.

Reflect:
- What if a wider robot cannot fit the shortcut—how would you decide the best width?
- Can a frame be very rigid but still be a poor competition design? Why?

DAY 7 — TWO MOTORS OR FOUR?
Phase: Week 2 / Competition drivetrain design

Think First: Allocate a maximum of six motors among drive, intake, lift, and any other job. Write what you gain and risk with each allocation.

Concepts: 2-motor versus 4-motor drives; motor groups; traction versus speed; wheel diameter and tread; omni versus traction wheels; gear ratio; turning scrub; rigidity and alignment; center of gravity; footprint/shortcut requirements; battery and reliability; motor-budget tradeoffs.

Learn / video targets, ranked:
1. NEW: VEX IQ competition drivetrain comparison with 2- and 4-motor examples.
2. Reuse "First Robot Build Standard Drive Base" for concrete layout.
3. Reuse "BaseBot Assembly" or "Gen2 BaseBot Build" for correct construction.
4. NEW: VEX IQ wheel choice/traction/omni explanation.
Video search types/queries: "VEX IQ 2 motor vs 4 motor drivetrain"; "VEX IQ competition drivetrain wheel choice"; "VEX IQ traction wheel omni wheel comparison".

Connect the Dots: More drive motors can increase available torque and robustness, but the rule-limited motor budget means fewer powered mechanisms. Wheel size, gearing, mass, friction, and frame alignment can matter as much as motor count, so the answer must come from the Level Up job list and tests.

Reflect:

Connect the Dots: Linkages constrain a path rather than merely rotating one beam. DAY 11 — UNBOX FLOP LIKE A SYSTEMS ENGINEER
Phase: Week 3 / Phase C: Build, analyze, test, and improve Flop
Target time: 45-60 minutes

Hook (Socratic puzzle): The same pile of parts can become a robot that drives, lifts, intakes, scores, or fails quietly because one tiny spacer is missing. Before building, how can you tell which parts will become which robot jobs?

Think First: Sort the parts you expect Flop to use into four guessed groups: drive, arm, intake, electronics, and structure. Circle the parts you cannot name yet and predict which group they probably support.

Concepts: kit familiarity; official build instructions as a map; subsystem identification; drivetrain, arm, intake, Brain, Controller, battery, motors, sensors, shafts, collars, gears, wheels, beams, plates, pins, standoffs, spacers; build trays and part staging; checking inventory without losing momentum.

Learn / video targets, ranked:
1. Reuse "VEX IQ 2nd Gen Kit Walkthrough" for part recognition before touching the Flop instructions.
2. Reuse "What's in the Box" as a fast visual inventory check.
3. Reuse "Getting Started with VEX IQ Gen 2" for Brain, Controller, battery, and system setup context.
4. Reuse "Flop Part 1" only as a short preview of how individual parts become robot subsystems.
Video search types/queries: no new research required; use the official Flop 3D build instructions as the main non-video source.

Connect the Dots: A build instruction is not just a recipe; it is a sequence of subsystem decisions. If Arian can name what each part is doing before it disappears into the robot, he will debug faster later because he knows whether a problem belongs to structure, motion, power, control, or game interaction.

Try It: Create a "Flop subsystem map" before building. For each staged part group, write the likely subsystem, motion it supports, and one failure that part could prevent. Then open the official instructions and update the guesses in a second color as evidence appears.
